## 版本 2.0 — 2026-05-27

### 修改内容：项目重构为球形机器人 V1 框架

将项目从 ESP-IDF blink 示例彻底改造为球形机器人项目的软件架构框架。

**动机**：项目目标是做一个类似蔚来 NOMI 的球形机器人。初代（V1）要求：能听声辨位、通过步进电机水平旋转转向声源方向、有一块显示屏展示状态。本次改造先搭建完整的项目框架，暂不实现各组件内部逻辑。

**做了什么**：

1. **项目重命名**：`project(blink)` → `project(robot)`，构建产物从 `blink.bin` 变为 `robot.bin`。

2. **新增 4 个组件骨架**（`components/` 下）：
   - `robot_core`：主状态机，定义 `IDLE → LISTENING → LOCATING → TURNING → FACE_PERSON → IDLE` 五个状态，提供 `init/start/stop/get_state` 接口
   - `audio_locator`：双 INMP441 I2S 麦克风声源定位，TDOA 算法预留，提供 `init/get_angle/is_sound_detected` 接口
   - `motor_controller`：步进电机 + TMC2209 静音驱动，单轴水平旋转，提供 `init/turn_to_angle/return_to_center` 接口
   - `display_driver`：ST7789 SPI 显示屏（240×240），表情枚举预留，提供 `init/show_text/show_expression` 接口
   - 每个组件包含：`CMakeLists.txt`（构建定义）、`Kconfig`（引脚/参数配置）、`include/xxx.h`（公开 API 头文件）
   - 所有组件 **SRCS 为空**，V1 不包含内部实现

3. **主程序重写**：删除 `blink_example_main.c`，新建 `robot_main.c`。入口逻辑简化为：初始化 logger_wrapper → 初始化 robot_core → 启动状态机 → 空闲循环。

4. **清理 blink 残留**：
   - 删除 `main/blink_example_main.c`
   - 删除 `pytest_blink.py`（blink 集成测试）
   - 删除 8 个多余芯片的 `sdkconfig.defaults.*`（esp32/esp32c3/esp32c5/esp32c6/esp32c61/esp32h2/esp32p4/esp32s2），仅保留 `sdkconfig.defaults` 和 `sdkconfig.defaults.esp32s3`
   - 重写 `main/Kconfig.projbuild`（从 blink LED 配置 → 机器人配置）

5. **硬件选型确定**：
   - 显示屏：ST7789 1.54" 方形 240×240 SPI
   - 麦克风：INMP441 × 2（I2S MEMS，左右声道分离）
   - 电机：步进电机 + TMC2209 静音驱动（StealthChop 技术）
   - 机械结构：单轴水平旋转（pan only），球形外壳 + 底座

6. **Git 仓库初始化**：项目从无版本控制到完成初始提交。

## 版本 1.1 — 2026-05-26

### 修改内容：新增 logger_wrapper 日志包装组件

在项目的 `components/` 目录下新创建了一个名为 `logger_wrapper` 的自定义组件，用于包装 ESP-IDF 原生的 `esp_log` 日志模块。

**动机**：项目当前通过串口（UART）输出日志，一旦设备脱离调试环境，运行期间的日志就看不到了。我们希望把所有日志同时存到 PSRAM 中的一个环形缓冲区（ring buffer）里，这样后期可以通过其他接口（比如后续加的 Wi-Fi 或 BLE）把日志读出来，方便远程诊断。

**做了什么**：

1. 新建了 `components/logger_wrapper/` 组件，包含公开头文件、私有头文件、源文件和 Kconfig 配置。
2. `logger_wrapper.h` 包含原来的 `esp_log.h`，然后重新定义了 `ESP_LOGE`、`ESP_LOGW`、`ESP_LOGI`、`ESP_LOGD`、`ESP_LOGV` 五个宏。新宏在输出到控制台的同时，把日志也写入 PSRAM 环形缓冲区。
3. 环形缓冲区使用固定大小的槽位存储每条日志（时间戳 + 等级 + 标签 + 消息内容），用 FreeRTOS 互斥锁保证多任务安全。
4. 提供了 `logger_wrapper_init()`、`logger_wrapper_deinit()`、`logger_wrapper_get_count()`、`logger_wrapper_dump()`、`logger_wrapper_clear()` 五个公开 API，方便读取/清除存储的日志。
5. 如果 PSRAM 分配失败，日志功能不受影响——仍然正常输出到控制台，只是没有缓冲区存储。

## 版本 1.0 — 2026-05-26（初始状态）

### 项目创建

这是项目的初始状态，基于 ESP-IDF 官方 blink 示例创建。

**项目基本信息**：
- 芯片：ESP32-S3
- 框架：ESP-IDF v6.0.1
- 构建系统：CMake + Ninja + idf.py
- 项目名：blink
- 串口：COM11（115200 bps）

**已有功能**：
- LED 闪烁（支持 GPIO 直连 LED 或 WS2812 可寻址 LED 灯带）
- 通过 Kconfig 菜单配置 LED 类型、GPIO 引脚号、闪烁周期
- 使用 `espressif/led_strip` v3.0.3 组件驱动 WS2812
- 通过 ESP-IDF 标准日志系统（`esp_log`）输出日志到串口

**PSRAM 配置**：
- 已启用（八线 Octal 模式，80 MHz，时钟引脚 GPIO 30，片选引脚 GPIO 26）
- 使用 MALLOC 模式——所有 `malloc()` 默认从 PSRAM 分配（大于 16KB 阈值的分配）
- 内部保留 32KB SRAM 用于关键操作

**构建模式**：
- 启用了最小化构建（`MINIMAL_BUILD ON`）——只有被显式依赖的组件才会被编译

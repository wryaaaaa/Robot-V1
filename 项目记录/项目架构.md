## 项目简介

**球形机器人 V1**（灵感来源：蔚来 NOMI），ESP32-S3 主控。核心功能：双麦克风听声辨位 + 步进电机水平旋转转向声源 + 显示屏展示状态。

## 机器人状态机

```
IDLE ──(检测到声音)──→ LISTENING ──(采集完成)──→ LOCATING
  ↑                                                  │
  │                                        (计算出声源角度)
  │                                                  │
  │                                                  ↓
FACE_PERSON ←──(到达目标角度)── TURNING ←─────────────┘
  │
  ↓ (短暂停留后)
 IDLE
```

## 当前实现的功能

### V2.0 — 机器人项目框架搭建

- **robot_core**：主状态机组件，定义 `IDLE → LISTENING → LOCATING → TURNING → FACE_PERSON` 五个状态
- **audio_locator**：声源定位组件骨架，预留双 INMP441 I2S 麦克风接口和 TDOA 算法
- **motor_controller**：电机控制组件骨架，预留 TMC2209 步进驱动接口
- **display_driver**：显示屏驱动组件骨架，预留 ST7789 SPI 接口和表情枚举
- **状态**：仅框架（头文件 + CMakeLists + Kconfig），无内部实现

### 已有功能（继承自 blink 时代）

- **logger_wrapper**（v1.1）：PSRAM 环形日志缓冲区，双输出（控制台 + 缓冲区）
- FreeRTOS 任务管理
- PSRAM 内存分配

## 关键设计模式与约束

1. **最小化构建（MINIMAL_BUILD ON）**：只有被 `main/CMakeLists.txt` 的 `REQUIRES` 显式声明的组件才会被编译。新增组件必须显式添加依赖。

2. **协调者模式**：`robot_core` 作为中心协调器，内部运行状态机，调度三个外设组件。各组件之间不直接通信，通过 `robot_core` 中转。

3. **IDF v6.x 驱动模型**：原生 `driver` 组件已被拆分为独立的 `esp_driver_*` 组件（如 `esp_driver_gpio`、`esp_driver_spi`、`esp_driver_i2s`）。编写代码时直接依赖具体的 `esp_driver_*` 组件。

4. **PSRAM 内存策略**：
   - 配置为 MALLOC 模式——`malloc()` 默认从 PSRAM 分配
   - 小于 16 KB 的分配使用内部 SRAM
   - 内部保留 32 KB SRAM 用于 DMA 等关键操作
   - 中断服务程序（ISR）中严禁使用 PSRAM

5. **日志宏包装模式**：通过 `#undef` 后重新定义宏的方式实现日志拦截，用户代码只需更改 `#include` 路径。

6. **V1 框架先行**：当前版本仅定义接口和构建骨架，不实现内部逻辑。后续逐步填充各组件的实际驱动代码。
